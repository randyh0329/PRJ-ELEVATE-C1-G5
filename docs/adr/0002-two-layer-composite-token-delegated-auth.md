# ADR 0002: Two-Layer Composite Token Delegated Authorization

## Status
Accepted

## Context
Downstream enterprise systems (WorkWeek and ServiceImmediately) require both proof of calling workload authenticity and the authenticated employee identity. Relying on model-generated employee IDs introduces catastrophic IDOR (Insecure Direct Object Reference) vulnerabilities where an LLM could query or modify arbitrary employee profiles.

## Decision
Enforce a 2-Layer Composite Token Architecture (SDD §4.1):
1. **Layer 1: Workload Identity**: Google Cloud Workload Identity Federation OIDC token passed in the `Authorization: Bearer <oidc_token>` header.
2. **Layer 2: Subject Assertion**: Short-lived (120s) RS256-signed JWT passed in `X-Subject-Assertion`.
   - The subject claim `sub` is bound **server-side at the Ingress API Gateway** from the authenticated employee session.
   - It is **NEVER** accepted as a tool parameter or generated by the LLM.
   - Replay defense is enforced via a unique `jti` nonce recorded in Firestore with a 120-second TTL.

## Consequences
- Eliminates IDOR vulnerabilities completely at the protocol level.
- Downstream adapters and mock backends resolve subject identity strictly from verified assertions.
- Mitigates token replay attacks.
